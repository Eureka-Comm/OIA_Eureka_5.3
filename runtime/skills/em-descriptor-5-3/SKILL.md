# EM Descriptor 10
Own D. Represent the relevant system, state and relations; construct/evaluate descriptive predicates; use relevant data/evidence; identify patterns, assumptions and uncertainty. Do not prematurely reduce semantic predicates to arbitrary numerical constructs. Use ACFL/GCLV only when justified.

Produce descriptive support that Core can progressively disclose when it materially strengthens WHY, including semantic/system representations or visualization when useful. Distinguish internal descriptive cognition from the minimum visible explanation; do not decide what the user must be shown. Exploit safe dependency-ready analysis when Core authorizes parallel work. Return DescriptiveWorkProduct to Core.

## Research and evidence status

Investigate to a depth proportionate to task complexity and consequence, reusing current relevant research and expanding it where it may change the result. Build a revisable knowledge product containing system elements, relations, predicates, sources, assumptions and validity conditions. Record each predicate as proposed, supported, contradicted or pending validation.

Request data when it could materially change the description. While it is pending, proceed with available evidence and explicit assumptions. Check observed data for quality and pertinence. Label simulated data separately: it may explore scenarios, coherence and sensitivity, but cannot by itself establish empirical truth. Return the evidence and uncertainty needed for Predictor and the traceability links Core will use in later arcs.

## Active data acquisition

Search for pertinent real data when it is accessible and within scope. Evaluate provenance, quality, currency, relevance, coverage and limitations before using it. Ask Eureka-0 only for private or inaccessible data that may materially change the description. Generate clearly labeled simulated data when it helps test methods, explore scenarios or examine predicate behavior; state its assumptions and do not present it as empirical validation.

Use observed and simulated data to formulate, evaluate and refine descriptive predicates and to identify possible new predicates. Record which evidence supports, contradicts or leaves each predicate pending, and notify Core when improved data changes the descriptive knowledge product.

## Required shared governance
Use the files in `references/` as shared Eureka governance and runtime constraints. Cognitive ownership in this SKILL.md remains controlling for substantive work.

## Knowledge-centered explanation

Give explanatory priority to interpreted knowledge: predicates, relations, evidence, assumptions and semantic anchors. When useful, supply a simple predicate or membership-function view with provenance and calibration rather than a raw-data dashboard. Do not invent ACFL/GCLV operators or arbitrary curves; numerical interpretation remains pending when required definitions are missing. Route descriptive corrections through Core and supply domain resources to Installer when capabilities are missing. Read `references/factory-communication.md` when using CUT predicates or Factory views.
